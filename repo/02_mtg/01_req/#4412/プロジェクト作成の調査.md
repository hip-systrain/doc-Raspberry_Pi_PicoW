# VS Code における Raspberry Pi Pico W / Pico 2 W プロジェクト作成ガイド

## 1. 環境確認からプロジェクト作成までの手順

1. **拡張機能のインストール確認**
   - VS Code 左側のアクティビティバーから「拡張機能（Extensions）」を開く。
   - `Raspberry Pi Pico`（Raspberry Pi 公式拡張機能）がインストール済みであることを確認する（未インストールの場合はインストールし、初回起動時に `~/.pico-sdk` 配下へ SDK とツールチェーンが自動導入されるのを待つ）。
2. **新規プロジェクト作成ウィザードの起動**
   - アクティビティバーの **Raspberry Pi Pico アイコン** をクリックする。
   - 「Quick Access」メニュー内の **「New C/C++ Project」** を選択する。
3. **基本設定・ターゲットの指定**
   - **Name**: プロジェクト名を入力する（半角英数字・アンダースコア推奨、スペース不可）。
   - **Board type**: 使用するマイコンボードに合わせて選択する。
     - Raspberry Pi Pico W の場合: `Pico W`
     - Raspberry Pi Pico 2 W の場合: `Pico 2 W`
   - **Architecture**: `Board type` に応じて選択する（`Pico 2 W` 選択時などに表示）。
     - 通常はデフォルトの `ARM`（Cortex-M33）を選択する（RISC-V コアである Hazard3 を使用する場合のみ `RISC-V` を選択）。
   - **Location**: プロジェクトフォルダを生成する親ディレクトリを選択する。
   - **Select Pico SDK version**: 使用する Pico SDK のバージョンを選択する（`Pico 2 W` を使用する場合は **SDK 2.0.0 以降** を選択）。
4. **機能・開発環境オプションの設定**
   - **Features**: プロジェクトに組み込むハードウェア・ミドルウェア機能（SPI、I2C、DMA、PIO、FreeRTOS など）にチェックを入れる（必要なライブラリが `CMakeLists.txt` の `target_link_libraries` へ自動追加される）。
   - **Stdio support**: `printf` などの標準入出力の経路を選択する。
     - `Console over UART`: UART ピン経由でシリアル出力する場合に選択。
     - `Console over USB`: USB ケーブル経由でシリアルモニタへ出力する場合に選択。
   - **Code generation options**: コード生成に関するオプションを指定する。
     - `Generate C++ code`: C++ を使用する場合はチェックを入れる（メインソースが `.cpp` になり、`CMakeLists.txt` に C++ 設定が追加される）。
     - `Run from RAM`: プログラムをフラッシュメモリではなく RAM 上で実行する場合に選択（通常はオフ）。
     - `Add examples from Pico Examples`: サンプルコードをテンプレートに含める場合に選択。
   - **Debugger**: 実機デバッグに使用するデバッガの種類（`DebugProbe (CMSIS-DAP)` や `SWD` など）を選択する（`launch.json` の構成に反映される）。
   - **CMake Tools**: VS Code の「CMake Tools」拡張機能と連携してビルド構成を管理する場合はチェックを入れる（通常はオフのままで Pico 拡張機能標準のタスクビルドを使用可能）。
5. **プロジェクトの生成**
   - 右下の **「Create」** をクリックする。
   - CMake の初期構成（Configure）が自動実行され、新しい VS Code ウィンドウでプロジェクトが開く。

## 2. ボード選択・オプション設定の補足

### ボード選択時の注意点（無印モデルとの違い）
- 無線機能なしの `Pico` / `Pico 2` と、無線機能付きの `Pico W` / `Pico 2 W` ではハードウェア構成が異なるため、必ず `W` 付きのボードタイプを選択する。
- ボード指定に応じて、`CMakeLists.txt` 内の `PICO_BOARD` 設定や無線ドライバ（`pico_cyw43_arch`）のリンク構成が自動的に切り替わる。

### Pico W / Pico 2 W における CYW43（無線チップ）の扱い
- Pico W および Pico 2 W では、オンボード LED が RP2040 / RP2350 本体ではなく無線チップ（CYW43）側に接続されている。
- Wi-Fi 通信を行わずオンボード LED の点灯（Lチカ）のみを行う場合でも、CYW43 ドライバの初期化（`cyw43_arch_init()`）が必要となるため、正しいボードタイプを選択して無線用ライブラリをリンクさせることが重要になる。

### Architecture の違い（Pico 2 W のみ）
- `Pico W`（RP2040）は ARM Cortex-M0+ のみのためアーキテクチャ選択はないが、`Pico 2 W`（RP2350）はデュアルアーキテクチャを採用しており、`ARM`（Cortex-M33）と `RISC-V`（Hazard3）の切り替えが可能。標準的なライブラリ互換性を重視する場合は `ARM` を選択する。

## 3. 生成されたプロジェクトの初期フォルダ構成と詳細

### 全体像（C++ オプション有効時の構成例）

※ `.gitignore` は環境や拡張機能のバージョンによって自動生成されない場合があるため、Git 管理を行う際はルート直下へ手動で作成します。

```text
my_project/
├── .vscode/
│   ├── c_cpp_properties.json   # IntelliSense（コード補完・パス解決）設定
│   ├── extensions.json         # 推奨拡張機能の定義
│   ├── launch.json             # デバッガ（Debug Probe / OpenOCD）構成
│   ├── settings.json           # Pico 拡張機能・CMake・環境変数設定
│   └── tasks.json              # ビルド・フラッシュ書き込みタスク定義
├── build/                      # ビルド成果物（CMake / Ninja の出力先）
│   ├── CMakeCache.txt          # CMake の構成キャッシュ
│   ├── compile_commands.json   # コンパイルデータベース（IntelliSense 連携用）
│   ├── build.ninja             # Ninja ビルドスクリプト
│   └── ...                     # その他の中間ファイル（ビルド後に .uf2 / .elf が生成）
├── .gitignore                  # Git 管理対象外ファイル（build/ や環境依存設定）の指定
├── CMakeLists.txt              # プロジェクト全体の CMake ビルド設計図
├── my_project.cpp              # メインソースファイル（C の場合は my_project.c）
└── pico_sdk_import.cmake       # Pico SDK のパス解決・読み込み用スクリプト
```

### `.gitignore` の記載内容（Git 管理を行う場合）

ビルドごとに生成される `build/` ディレクトリや中間バイナリ、環境固有のパスが含まれる `.vscode/` 配下のファイルを除外対象として記載します。

```gitignore
# ビルド成果物・CMake 生成物
build/
*.uf2
*.elf
*.bin
*.hex
*.dis
*.map

# 環境依存パス（~/.pico-sdk 等）を含む設定を除外（共通設定のみ残す場合）
.vscode/*
!.vscode/extensions.json
!.vscode/tasks.json

# OS・エディタ固有の一時ファイル
.DS_Store
Thumbs.db
*~
*.swp
```

* **補足（`.vscode/` の扱い）**: 個人開発で環境が固定されている場合は `.vscode/` を除外せずすべてコミットしても問題ありませんが、複数 PC やチーム開発（Windows / macOS / Linux 混在）ではローカルパス（`settings.json` / `c_cpp_properties.json`）が競合するため除外するのが安全です。

## 4. 各ファイル・ディレクトリの役割

### ルート直下のファイル

| ファイル名 | 役割 |
| :--- | :--- |
| `CMakeLists.txt` | プロジェクト全体のビルド設計図。ターゲットボード（`pico_w` / `pico2_w`）、SDK バージョン、`Features` で選択したリンクライブラリ、`Stdio support` の有効化設定などを定義する。新規ファイル追加時は `add_executable()` に追記する。 |
| `my_project.cpp` / `.c` | エントリーポイント（`main` 関数）を含むメインのソースファイル。選択したオプションに応じた初期化コードの雛形が生成される。 |
| `pico_sdk_import.cmake` | ローカル環境内の Pico SDK パスを解決し、CMake ビルドシステムへ読み込ませるブリッジ用スクリプト。通常は手動編集不要。 |
| `.gitignore` | Git 管理の対象外とするパス（主に `build/` ディレクトリなど）を定義する。 |

### 生成されるディレクトリ

| ディレクトリ名 | 役割 |
| :--- | :--- |
| `build/` | CMake と Ninja によるビルド成果物（中間オブジェクト、実行バイナリ）の出力先。BOOTSEL モード書き込み用の **`.uf2` ファイル** や、デバッガ書き込み用の **`.elf` ファイル** がここに生成される。クリーンビルド時は中身を削除して再構成する。 |
| `.vscode/` | VS Code 上での開発・ビルド・デバッグ環境を統合するための設定ファイル群を格納するディレクトリ。 |

### `.vscode/` 配下の各設定ファイル

| ファイル名 | 役割 |
| :--- | :--- |
| `c_cpp_properties.json` | IntelliSense（コード補完・定義ジャンプ）用のインクルードパスやコンパイラ定義を管理する。 |
| `settings.json` | 選択したボード種別、SDK バージョン、ツールチェーンパスなど、Pico 拡張機能固有のプロジェクト設定を保持する。 |
| `tasks.json` | ビルド実行時（Compile ボタン押下時など）に呼び出される CMake / Ninja コマンドのタスク定義。 |
| `launch.json` | デバッガ（Raspberry Pi Debug Probe や OpenOCD など）を用いた実機デバッグ（ブレークポイント・ステップ実行）の構成ファイル。 |
| `extensions.json` | このプロジェクトを開く際に推奨される拡張機能の一覧定義。 |
