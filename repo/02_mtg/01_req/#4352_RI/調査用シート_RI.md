## RTOSなしの開発について		
RTOS（Real-Time Operating System：リアルタイムOS）を使用せず、マイコン上でプログラムを実行する方式  
RTOSなしの場合、基本的にはプログラムの開始地点である main() 関数から処理を開始し、	必要な初期化を行った後、メインループで処理を繰り返す。	  

## RTOSなしとRTOS使用の違い		
|比較項目	|RTOSなし |FreeRTOSあり|
|----|----|----|
|タスク管理	|開発者が実装	|RTOSが管理|  
|処理の実行順序|基本的に記述順|	スケジューラが管理|
|優先順位|	独自に制御|	タスクごとに設定|
|タスク切替|	自分で処理を構成|	RTOSが実施|
|メモリ管理|	必要な領域を設計|	タスク用スタックなども管理|
|プログラム構造|	比較的シンプル|	タスク単位で構成|
    
## RTOSなしの開発で行うプログラム  
C言語でRTOSなしのプログラムを作成する場合以下が基本の構造になる
```
int main()		
{		
    // 初期化処理		
    while (1)		
    {		
        // メイン処理		
    }		
    return 0;		
}
``` 		
- マイコンで使用するGPIOや通信機能などは、使用前に初期化する必要がある		
- 処理の順番や実行タイミングはプログラム側で制御する。		
- メイン処理に挿入したコードを処理していく		
- メイン処理に動作を複数組み込めば、上から順に処理を行う	  
※複数処理も可能		

プログラムの作成で一般的に利用する構成を以下にまとめる
|構成|	役割|  
|----|----|	
|ヘッダーファイルの読み込み|	使用するライブラリや関数の宣言	|
|定数・変数の定義|	プログラムで使用する値の定義|
|初期化処理|	GPIOや通信機能などの初期設定|
|メインループ|	メインとなる処理の繰り返し|
|関数|	個別の処理をまとめて管理|  

## Pico SDKを使用したC言語のプログラム  
  Pico SDKとは、Raspberry Pi Picoシリーズ向けに提供されているC/C++言語用の開発キット（ソフトウェア開発環境・ライブラ群）
  - C言語でマイコンの機能を操作するためのAPIやライブラリが用意されている。  
  例えば、次のような機能が利用できる。
    |機能|内容|
    |----|----|
    |GPIO| 入出力端子の制御|
    |UART| シリアル通信|
    |I2C|	センサーなどとの通信|
    |SPI|	周辺機器との通信|
    |PWM|	LEDの明るさやモーターの制御|
    |Timer| 時間を管理した処理|
    |IRQ|	割り込み処理|
    |Multicore| 2つのCPUコアを使用した処理|

  - Pico SDKを使用したC言語のプログラムは以下の流れで作成する。
    1. C言語でプログラムを作成
    GPIOや通信などの処理を記述する。  
    2. Pico SDKのAPIを利用
    マイコンの機能を操作するためのライブラリを使用する。
    3. ビルド
    CMakeなどを利用してコンパイルし、実行可能なファイルを生成する。
    4. Picoへ書き込み
    UF2形式などのファイルをマイコンに書き込む。
    5. プログラムの実行
    マイコンが書き込まれたプログラムを実行する。
    
#### タスクスケジューラによる処理管理  
  - RTOSなしでも、メインループに処理を複数挿入することで2つ以上の処理を実施できる
  - RTOSが提供するタスクスケジューラが無いため、メインループ内でタイマーや割り込みなどを用いて処理のタイミングを指定する必要がある  

#### タスクの並行管理  
複数の処理を切り替えながら進めることでプログラムを効率よく進める
タスクの平行管理は主に以下の3つがある
1. メインループによる処理の切り替え
1. タイマー
1. 割込み
  
- メインループによる処理の切り替え
  メインループ内に複数の処理を挿入し、各処理を順番に実行させて、複数の処理が同時に進んでいるように動作させる
- タイマー  
  指定した時間になると処理が行われる
  一般的にはメインループに入る前に実行する。  
  指定した時間になったら特定の処理が行える。
  時間が来るまではメインループで別の処理を行える
- 割込み
  条件を満たすと処理が行われる。
  こちらも一般的にはメインループに入る前に実行する。  
  メインループの処理中に割込みの条件を達成すると、割込みで設定した処理を優先して実行する

#### 平行管理と並列処理の違い
- 平行管理
  複数の処理を切り替えながら進めること
- 並列管理
  複数の処理を実際に同時実行すること

#### マルチコア処理  
Pico SDKには、2つのCPUコアを使用するためのマルチコアAPIが用意されている  
以下のプログラムのようにcore1で実行する処理とcore0で実行する処理をそれぞれ独立して動作させられる
```
#include "pico/stdlib.h"
#include "pico/multicore.h"

void core1_task() {
    while (true) {
        // Core 1で実行する処理
    }
}

int main() {
    stdio_init_all();

    multicore_launch_core1(core1_task);

    while (true) {
        // Core 0で実行する処理
    }
}
```
RTOSなしの場合、コア間の同期やデータ共有などを自分で管理する必要がある		

## 用語解説  
調査中に気になった単語などを以下にまとめる
#### GPIO（General Purpose Input/Output）  
GPIOは、マイコンと外部の電子部品を接続して、信号の入出力を行うための端子。  
- ボタン、LED、センサーなどを接続し、電気信号を読み取ったり、出力などが可能。  
 - マイコンボードの両端にある端子の一部がGPIO端子となる  

#### CMAKE
プログラムをビルドするために必要な設定を管理し、ビルド環境を生成するツール  
- CMakeLists.txtにビルド対象のソースファイルなどの情報を記載し、別のビルドを行う機能がその情報を元にビルドを実施する。  
- VS CodeのRaspberry Pi Pico拡張機能を使用する場合、プロジェクト作成時にCMakeLists.txtが自動生成され、ビルド時にもCMakeが利用される。　　
そのため、通常はCMakeのコマンドを手動で実行する必要はない。
