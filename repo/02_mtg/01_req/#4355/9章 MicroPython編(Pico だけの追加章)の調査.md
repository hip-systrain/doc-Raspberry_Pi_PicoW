# Raspberry Pi Pico W / Pico 2 W MicroPython 開発手順書

## 1. 事前準備：MicroPython ファームウェアの書き込み

Raspberry Pi Pico W と Pico 2 W は搭載されているマイコンチップ（RP2040 / RP2350）が異なるため、**必ずお使いのボードに対応したファームウェア（`.uf2` ファイル）** を用意してください。

### 1-1. ファームウェアのダウンロード
[Raspberry Pi 公式ドキュメント（MicroPython ページ）](https://www.raspberrypi.com/documentation/microcontrollers/micropython.html) の「Install MicroPython」セクションから、該当するボードの最新安定版（Releases）の `.uf2` ファイルをダウンロードします。

* **Raspberry Pi Pico W 用**: `RPI_PICO_W-xxxxxxxx-vX.XX.X.uf2`（[直接ダウンロードページ](https://micropython.org/download/RPI_PICO_W/)）
* **Raspberry Pi Pico 2 W 用**: `RPI_PICO2_W-xxxxxxxx-vX.XX.X.uf2`（[直接ダウンロードページ](https://micropython.org/download/RPI_PICO2_W/)）

> **注意:** Wi-Fi機能を持たない無印版（`RPI_PICO` / `RPI_PICO2`）のファイルを書き込むと、オンボードLEDの制御（`Pin("LED")`）や無線機能が正しく動作しません。ファイル名に **`_W`** が含まれていることを必ず確認してください。

### 1-2. ボードへの書き込み手順
1. PCとボードを接続していない状態で、ボード上の **BOOTSEL ボタン** を押し続けます。
2. BOOTSEL ボタンを押したまま、データ通信対応の USB ケーブルで PC とボードを接続します。
3. PC 側に新しいドライブ（`RPI-RP2` または `RP2350`）が認識されたら、BOOTSEL ボタンを離します。
4. ダウンロードした `.uf2` ファイルを、認識されたドライブへドラッグ＆ドロップ（コピー）します。
5. コピーが完了すると自動的にドライブの接続が解除され、MicroPython が起動します。

## 2. 開発環境の構築（VS Code + Raspberry Pi Pico 拡張機能）

本手順では、公式の **Raspberry Pi Pico** 拡張機能を使用して MicroPython プロジェクトを作成します。

### 2-1. 拡張機能のインストール
1. VS Code を起動し、左側のアクティビティバーから **拡張機能（Extensions）** アイコン（または `Ctrl + Shift + X`）を開きます。
2. 検索バーに `Raspberry Pi Pico` と入力し、公式拡張機能 **Raspberry Pi Pico**（発行元: `Raspberry Pi`）をインストールします。
   * ※MicroPython の実行・通信に必要な連携拡張機能（`MicroPico` や `Python` など）も自動で導入されます。

### 2-2. MicroPython プロジェクトの作成
1. VS Code の左側のアクティビティバーに追加された **Raspberry Pi Pico アイコン** をクリックします。
2. メニュー内の **General** から **`New MicroPython Project`** を選択します（初回起動時、必要なツールのダウンロードが自動で行われるため完了まで待機します）。
3. プロジェクト作成画面が表示されたら、以下の項目を設定して **`Create`** をクリックします。
   * **Name**: 任意のプロジェクト名（例: `pico_micropython_test`）
   * **Location**: プロジェクトフォルダを保存する親ディレクトリ
4. 作成が完了すると、自動的に新しいウィンドウでプロジェクトが開き、サンプルファイルや補完用の設定ファイルが生成されます。

### 2-3. ボードとの接続確認
1. MicroPython ファームウェアを書き込み済みのボードを、データ通信対応の USB ケーブルで PC に接続します。
2. VS Code 下部のステータスバーに **`Pico Connected`** と表示されれば接続完了です。
   * ※**`Pico Disconnected`** と表示されている場合は、同表示をクリックして手動で再接続を試みます。

## 3. 基本操作

### 3-1. 対話モード（REPL）とは
**REPL（アール・イー・ピー・エル）** とは、マイコン上で MicroPython と対話しながらプログラムを実行できる **対話型実行環境（インタラクティブシェル）** のことです。

名称は以下の 4 つの頭文字に由来しています。
* **R**ead（入力を読み込む）: ユーザーが入力した Python の 1 行（または数行）を読み取ります。
* **E**val（評価・実行する）: 読み取ったコードをボード上の MicroPython が実行します。
* **P**rint（結果を出力する）: 実行結果や戻り値、エラー内容を画面（`>>>` の下）に表示します。
* **L**oop（繰り返す）: 次の入力待ち状態（`>>>`）に戻り、一連の流れを繰り返します。

#### 通常のファイル実行（`Run` / `main.py`）との違い
* **ファイル実行**: プログラム全体をまとめて書き、実行または保存して動かします。完成した処理や自動実行させたい処理に向いています。
* **REPL**: ピンの状態確認や関数・計算のテストなどを **1 行ずつ即座に試せる** ため、「LED が光るか試す」「センサーの値をちょっと覗く」「エラーの原因を切り分ける」といった場面で非常に役立ちます。

### 3-2. REPL の使い方
REPL（Read-Eval-Print Loop）を使うと、PC からコマンドを1行ずつ送信してボード上で即座に実行結果を確認できます。

1. VS Code 下部のステータスバーにある **`vREPL`** をクリックするか、画面下部のターミナルパネルで **`MicroPico (REPL)`** タブを開きます。
2. プロンプト（`>>>`）が表示されたら、以下のコードを入力して `Enter` を押します。
   ```python
   print("Hello, Pico!")
3. すぐに **Hello, Pico!** と返ってくれば通信は正常です。

### 3-3. ボードへのファイル保存と実行
PC 上で作成した Python ファイルをボード内のフラッシュメモリへ転送・保存します。

1. VS Code のエクスプローラー上で、任意のテスト用ファイル（例: `test.py`）を作成し、コードを記述して保存（`Ctrl + S`）します。
   * ※プロジェクト作成時に自動生成されたサンプルファイル（`blink.py`）を編集して試すこともできます。
2. **一時実行（ボードに保存せずテスト実行）**:
   * エディタでファイルを開いた状態で、ステータスバーの **`Run`** をクリックすると、ボード上でプログラムが実行されます（停止は **`Stop`** または REPL 上で `Ctrl + C`）。
3. **ボードへの保存（アップロード）**:
   * エクスプローラーでファイルを右クリックし、**`Upload file to Pico`** を選択します。
   * ステータスバーの **`Toggle Pico-FS`** をクリックすると、現在ボード内に保存されているファイル一覧を確認できます。

### 3-4. `boot.py` と `main.py` による電源投入時の自動実行
MicroPython は電源投入（またはリセット）時に、ボード内のルートディレクトリにある **`boot.py`** と **`main.py`** を決まった順序で自動的に探し、実行する仕様になっています。PC から切り離して単体で動作させたい場合はこの仕組みを利用します。

#### 起動時の実行順序と使い分け
1. **`boot.py`（最初に実行）**:
   * システムの初期設定（USB 動作モードの変更や周波数設定など、アプリ起動前に一度だけ行う環境設定）を記述するファイルです。
   * **通常のアプリケーション開発では作成・編集する必要はありません。**
2. **`main.py`（`boot.py` の後に実行）**:
   * メインのプログラム（Lチカやセンサー制御などの本体処理）を記述するファイルです。
   * 自動実行させたいプログラムは、基本的にすべて **`main.py`** として保存します。

> **注意:** `boot.py` に無限ループ（`while True:`）やエラーになる処理を記述すると、その後の `main.py` の実行や USB 通信（REPL 接続）まで到達できなくなり、ファームウェアの再書き込みが必要になる場合があります。特別な理由がない限り **`main.py` のみを使用してください。**

#### `main.py` の書き込みと自動実行の手順
1. PC 側の作業フォルダに **`main.py`** というファイル名でプログラムを作成します。
2. `main.py` を右クリックし、**`Upload file to Pico`** を選択してボードに書き込みます。
3. ボードの USB ケーブルを一度抜き、再度 PC または USB モバイルバッテリーなどに接続します（または REPL 上で `Ctrl + D` を押してソフトリセットします）。
4. PC 側で実行操作を行わなくても、起動と同時に `main.py` が自動的に実行されます。

> **自動実行の停止・上書き方法:**
> `main.py` 内で無限ループ（`while True:`）を実行している場合、起動直後から処理が占有されます。再度 VS Code から操作やファイル書き込みを行いたい場合は、ステータスバーの **`Stop`** を押すか、REPL 画面をクリックして **`Ctrl + C`** を押して実行中のプログラムを強制停止させてください。

### 3-5. 機器の接続・切断時の注意点とトラブル対処

PC（VS Code）とボードの接続・切断時には、シリアル通信やフラッシュメモリの仕様上、以下の問題が発生することがあります。

#### 1. 接続できない（`Pico Disconnected` のまま変わらない）
* **原因**: シリアルポート（COMポート）は同時に1つのソフトからしか接続できない仕様のため、**他のソフト（Tera Term、Thonny など）や別の VS Code ウィンドウ**がすでにポートを使用していると接続に失敗します。
* **対処**: 他の通信ソフトや別ウィンドウをすべて閉じた状態で、ステータスバーの `Pico Disconnected` をクリックして再接続してください。

#### 2. 接続はできるが、ファイルの書き込みや一覧表示が失敗する
* **原因**: ボード内の `main.py` が無限ループ（`while True:`）を実行中の場合、処理が占有されて PC からのファイル操作を受け付けられなくなります。
* **対処**: ステータスバーの **`Stop`** をクリックするか、REPL 画面で **`Ctrl + C`** を押してプログラムを停止させてから操作してください。

#### 3. 切断時のデータ破損（書き込み中のケーブル引き抜き厳禁）
* **原因**: ファイルのアップロード中（`Upload file to Pico`）や、プログラムからボード内ファイルへ書き込みを行っている最中に USB ケーブルを抜くと、**ボード内のファイルシステムが破損**し、ファイルが消えたり起動しなくなったりすることがあります。
* **対処**: ケーブルを抜く際は、必ず転送完了を確認し、実行中のプログラムを **`Stop`（または `Ctrl + C`）で停止してから** 安全に抜いてください。
  * ※万が一ファイルシステムが破損して起動しなくなった場合は、`BOOTSEL` ボタンを押しながら接続し、`.uf2` ファームウェアを再書き込みすることで復旧できます。

## 4. 実践題材（C/C++ と同じ題材を MicroPython で実装）

C/C++ 開発と同じ 4 つの基本題材を MicroPython で作成し、動作を確認します。

### 題材1：LED 点滅（Lチカ）
オンボード LED を 0.5 秒間隔で点滅させます。

* **使用ピン**: オンボード LED（`"LED"`）
* **サンプルコード（`ex1_blink.py`）**:
  ```python
  from machine import Pin
  import time

  # Pico W / Pico 2 W のオンボードLEDは "LED" を指定
  led = Pin("LED", Pin.OUT)

  while True:
      led.toggle()      # 点灯・消灯を反転
      time.sleep(0.5)   # 0.5秒待機
  ```
* **確認方法**: `Run` をクリックし、ボード上の LED が 0.5 秒ごとに点滅すれば成功です。

---

### 題材2：ボタン入力
タクトスイッチの押下状態を判定し、押している間だけオンボード LED を点灯させます。内蔵プルアップ抵抗（`Pin.PULL_UP`）を使用するため、スイッチの片側を **GP15**、もう片側を **GND** に接続します。

* **使用ピン**:
  * ボタン入力: `GP15`（プルアップ設定：未押下時 `1` / 押下時 `0`）
  * LED 出力: オンボード LED（`"LED"`）
* **サンプルコード（`ex2_button.py`）**:
  ```python
  from machine import Pin
  import time

  led = Pin("LED", Pin.OUT)
  button = Pin(15, Pin.IN, Pin.PULL_UP)

  while True:
      if button.value() == 0:   # プルアップのため、押されたら 0 (Low) になる
          led.value(1)          # LED点灯
      else:
          led.value(0)          # LED消灯
      time.sleep(0.02)          # チャタリング防止の短い待機（20ms）
  ```
* **確認方法**: `Run` をクリック後、ボタンを押している間だけ LED が点灯すれば成功です。

---

### 題材3：UART（文字の送信）
UART0 を使用して、1 秒ごとに文字列を送信します。USB-シリアル変換モジュールやロジックアナライザを接続するか、**GP0（TX）と GP1（RX）をジャンパ線で直結（ループバック）** して受信確認を行います。

* **使用ピン（UART0）**:
  * TX（送信）: `GP0`
  * RX（受信）: `GP1`
* **通信設定**: ボーレート `115200 bps`、データ長 `8bit`、パリティなし、ストップビット `1`
* **サンプルコード（`ex3_uart.py`）**:
  ```python
  from machine import UART, Pin
  import time

  # UART0 を初期化（TX=GP0, RX=GP1）
  uart = UART(0, baudrate=115200, tx=Pin(0), rx=Pin(1))

  count = 0
  while True:
      msg = f"Hello UART! count={count}\r\n"
      uart.write(msg)                         # 文字列を送信
      print("Sent:", msg.strip())             # 確認用にREPLへ出力

      # ループバック（GP0とGP1を直結）している場合の受信確認
      if uart.any():
          received = uart.read()
          print("Received:", received)

      count += 1
      time.sleep(1.0)
  ```
* **確認方法**: `Run` をクリックし、REPL 画面に送信ログ（および直結時は受信ログ `b'Hello UART! ...'`）が 1 秒ごとに表示されれば成功です。

---

### 題材4：タイマ割込み
`while True` 内の `time.sleep()` を使わず、ハードウェアタイマ（`machine.Timer`）による定期割込みでオンボード LED を点滅させます。メインループを止めずにバックグラウンドで一定周期の処理を実行できます。

* **使用機能**: `machine.Timer`（周期 `500ms` = `2Hz`）
* **サンプルコード（`ex4_timer.py`）**:
  ```python
  from machine import Pin, Timer
  import time

  led = Pin("LED", Pin.OUT)

  # タイマ割込み時に呼び出されるコールバック関数
  def on_timer(timer):
      led.toggle()

  # タイマ初期化（周期500msごとに on_timer を実行）
  tim = Timer()
  tim.init(period=500, mode=Timer.PERIODIC, callback=on_timer)

  # メインループは別の処理が可能
  try:
      while True:
          print("Main loop running...")
          time.sleep(2.0)
  except KeyboardInterrupt:
      # Ctrl+C で停止した際にタイマを解放
      tim.deinit()
      led.value(0)
      print("Stopped.")
  ```
* **確認方法**: `Run` をクリックすると、メインループの `print`（2秒間隔）とは独立して、LED が 0.5 秒ごとに点滅すれば成功です。

## 5. デバッグの方法

MicroPython では C/C++（SWD デバッガによるステップ実行）とは異なり、**USB シリアル経由の REPL と `print()` 文を使った対話的デバッグ** が基本となります。

### 5-1. `print()` による変数の状態・通過確認（プリントデバッグ）
プログラム内の確認したい箇所に `print()` を記述すると、VS Code 下部の **`MicroPico (REPL)`** ターミナルにリアルタイムで出力されます。

```python
val = button.value()
print(f"[DEBUG] button={val}")  # 変数の値をREPLに出力
```

### 5-2. エラー内容（トレースバック）の読み方
プログラム実行中にエラーが発生すると、実行が停止し REPL に以下のようなエラーメッセージ（Traceback）が表示されます。

```text
Traceback (most recent call last):
  File "<stdin>", line 12, in <module>
NameError: name 'led_pin' is not defined
```

* **`line 12`**: エラーが発生した行番号を示します。
* **`NameError: ...`**: エラーの種類と原因（この例では未定義の変数名を使用）を示します。
* VS Code 上の該当行番号を確認して修正し、再度 `Run` を実行します。

### 5-3. REPL を使った手動操作・切り分けテスト
コード全体を動かす前に、REPL 上で 1 行ずつコマンドを直接打ち込んでハードウェアの動作を切り分けることができます。

1. プログラムを `Stop`（または `Ctrl + C`）で停止します。
2. REPL のプロンプト（`>>>`）で、怪しい部分のコードだけを直接入力して試します。
   ```python
   >>> from machine import Pin
   >>> b = Pin(15, Pin.IN, Pin.PULL_UP)
   >>> b.value()   # ボタンを押さずに実行 -> 1 が返るか確認
   1
   >>> b.value()   # ボタンを押しながら実行 -> 0 が返るか確認
   0
   ```
3. ピンの配線ミスなのか、プログラムのロジックミスなのかを即座に切り分けることができます。
